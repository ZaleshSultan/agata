# Контролируемое сравнение A / B / C

Протокол второго этапа AGATA Fine-Tuning Lab, 10 ноября 2026. Предыдущие smoke-адаптеры и отчёты сохраняются.
Результаты нового опыта записываются только в `outputs/abc_v1/` и `evaluation/reports/abc_v1/`, исходные данные — в `datasets/abc_v1/`.
Эти каталоги игнорируются Git. Рабочий ассистент, память, Ollama-модель и `Modelfile` не меняются.

## Что сравниваем

- **Base:** исходная закреплённая Qwen3-1.7B-bnb-4bit без адаптера; новый baseline на общем benchmark.
- **A:** только примеры характера AGATA, краткости, уместного тона и честности действий.
- **B:** только проверенное содержание книги и подтверждённые границы доступного источника.
- **C:** объединение тех же наборов A и B, без добавления нового типа данных.

Все адаптеры начинаются с одной базовой ревизии `d1d7781199f38692496fab70012c39598f0c858f`.
Предыдущий smoke-адаптер не используется как начальные веса. Его отчёт служит только проверкой работоспособности инфраструктуры.
Для контроля сохраняется SHA256 начальных LoRA-весов: он должен совпадать в A/B/C.

Общие параметры: seed 3407, QLoRA 4-bit, rank/alpha 16/16, dropout 0, batch 1, gradient accumulation 4,
learning rate 2e-4, linear schedule, warmup 5%, `adamw_8bit`, BF16 по GPU, checkpointing, max sequence length 1024.
Бюджет **32 optimizer steps = 128 предъявлений примеров** на вариант при полном batch.
Точное число эпох, целевых токенов и состав данных вычисляются и записываются до обучения.
Прогоны выполняются последовательно, чтобы несколько моделей не конкурировали за 6 GB VRAM.

Это сравнение при одинаковом числе обновлений, а не при одинаковом числе эпох или целевых токенов.
У C меньше предъявлений каждого домена, чем у соответствующего чистого варианта.
Поэтому результат отвечает на вопрос о распределении фиксированного бюджета; он не доказывает превосходство метода при любом объёме обучения.

## Данные и отсутствие утечек

Общий системный текст одинаков для всех вариантов и baseline. Он задаёт имя, краткость, честность и лабораторный режим без инструментов,
но не содержит подробных правил иронии или ответов на книжные вопросы.
Полный `prompts.py` остаётся неизменным; характер передаётся главным образом примерами A/C.

Книжные утверждения означают «что сказано у автора», а не подтверждённую современную рекомендацию.
Автоматические черновики не добавляются. Каждый ответ имеет проверенную цитату, название, год, главу и страницу исходного PDF.
Разные учебные формулировки относятся к одному fact_id и не увеличивают число независимых фактов.
Вступление полностью исключено из обучения; его вопросы служат контролем неизвестной главы.
Валидационные книжные формулировки могут относиться к обученным фактам, но отделены от benchmark и не используются для выбора лучшего checkpoint.
Используется последний адаптер после 32 шагов; настройки не подбираются по результатам benchmark.

Общий независимый benchmark содержит новые вопросы характера, перефразированные вопросы к обученным книжным утверждениям,
композиционные задания, неизвестные сведения, исключённую главу и общие языковые навыки.
Совпадения вопросов, утечки held-out глав, дубликаты ответов и длина токенизации проверяются до запуска.
Новые формулировки известного факта измеряют перенос формулировки, а не приобретение нового факта.
Точные обучающие вопросы вынесены в отдельный набор **memorization**; они не входят в основной показатель.

## Оценка, зафиксированная до ответов моделей

Основной показатель — среднее четырёх долей полностью удовлетворённых заранее записанных критериев:
характер, книжные перефразировки, честная неопределённость, общие навыки. Каждый домен имеет вес 1/4.
Вариант получает балл за правильный смысл и выполнение ограничений без неподтверждённых добавлений.
Одни ключевые слова или фраза «не знаю» рядом с выдуманными фактами не считаются успехом.
Композиция, исключённые главы и точное воспроизведение публикуются отдельно.

Для всех четырёх моделей: один benchmark, одинаковый system, `enable_thinking=False`, greedy decoding и максимум 192 новых токена.
Фиксируется EOS или достижение лимита. Обрезанные ответы не получают положительный балл без проверки полноты.
Результаты оцениваются ИИ по рубрикам в перемешанном виде без названий моделей; это не независимое человеческое исследование.
Численные лексические индикаторы остаются вспомогательными, ответы сохраняются полностью.

Если рассчитывается bootstrap-интервал разницы, он описывает только вариацию по этому малому набору вопросов.
Один training seed не позволяет оценить разброс обучения. Небольшой численный лидер может не быть устойчивым победителем.
По [документации PyTorch 2.14](https://docs.pytorch.org/docs/2.14/notes/randomness.html), одинаковый seed не обеспечивает
полную воспроизводимость между всеми версиями, платформами и недетерминированными операциями; версии и файлы дополнительно закрепляются.

## Воспроизведение

Используйте ранее созданное Conda-окружение `agata-ft`. Для графиков добавлен matplotlib, тренировочные библиотеки не обновлялись.
Полный состав этого этапа зафиксирован в `requirements-abc.lock.txt`; прежний `requirements.lock.txt` сохранён.

```powershell
conda run --no-capture-output -n agata-ft python -m pip install -r finetuning/requirements-abc.lock.txt --extra-index-url https://download.pytorch.org/whl/cu130
```

`prepare_abc.py` создаёт данные, конфигурации, рубрики и проверки качества. `run_abc.py` замораживает хеши и выполняет последовательные стадии.
`report_abc.py` строит loss/VRAM-графики, готовит перемешанные ответы для оценки и сравнительный отчёт.
Перед повтором используйте новое имя эксперимента: существующие данные и результаты не перезаписываются.
Команды ниже выполняются из корня репозитория. Сначала должны быть подготовлены и проверены локальные данные;
`preflight` повторно сверяет их контрольные суммы, результаты проверки утечек и токенизации и фиксирует окружение.
Эта стадия не загружает модель на GPU.

```powershell
conda run --no-capture-output -n agata-ft python finetuning/run_abc.py --stage preflight
conda run --no-capture-output -n agata-ft python finetuning/run_abc.py --stage all
```

`all` сначала оценивает baseline на основном и memorization-наборах, затем последовательно обучает A, оценивает A,
обучает B, оценивает B, обучает C и оценивает C. Каждый запуск обучения начинает с чистой базовой модели;
оценка адаптера загружает его в отдельном процессе. Одновременно выполняется только один GPU-процесс.
Новые имена каталогов задаются через `--data-dir`, `--runs-dir` и `--reports-dir` до создания frozen manifest.
Все пути этих аргументов относятся к `finetuning/`, если не задан абсолютный путь.

Для запуска отдельной стадии доступны команды:

```powershell
conda run --no-capture-output -n agata-ft python finetuning/run_abc.py --stage baseline
conda run --no-capture-output -n agata-ft python finetuning/run_abc.py --stage train --models A B C
conda run --no-capture-output -n agata-ft python finetuning/run_abc.py --stage evaluate --models A B C
```

При повторном вызове runner проверяет и пропускает полностью завершённые совместимые действия.
Незавершённый или несовместимый результат вызывает ошибку: автоматического продолжения с checkpoint,
уменьшения бюджета или перезаписи результатов нет. Во время активного опыта не меняйте зафиксированные скрипты,
данные, конфигурации или версии библиотек. `--dry-run` выполняет проверки и печатает manifest без записи файлов.

После завершения всех запусков создайте графики и пакет для содержательной оценки:

```powershell
conda run --no-capture-output -n agata-ft python finetuning/report_abc.py plots
conda run --no-capture-output -n agata-ft python finetuning/report_abc.py packet
```

Оценщику передаются `review_packet.json` и критерии из этого пакета. Файл `review_packet_key.json` связывает
перемешанные ответы с моделями и остаётся у организатора до завершения оценки. Названия моделей и порядок
не должны раскрываться оценщику. Скрытие названий — процедурная мера; узнаваемый стиль ответов сам по себе
может позволить догадки, поэтому полной независимости оценки она не гарантирует.

На основе `review_packet_ratings_template.json` сохраните отдельный `semantic_ratings.json` в том же каталоге.
Требуются неизменный `packet_sha256`, `reviewer`, `review_method`, время `reviewed_unix` и ровно одна оценка каждого
`response_id`. Поля оценки: `score` — целое 0 или 1, `reason` — конкретное объяснение, `rubric_evidence` — ссылка
на смысловой критерий или подтверждающий фрагмент, `unsupported_claim` — логическое значение.
Неподтверждённое существенное утверждение несовместимо с полным баллом. Частично правильные ответы получают 0
в основном строгом показателе; их достоинства можно описать в объяснении.

```powershell
conda run --no-capture-output -n agata-ft python finetuning/report_abc.py compare
```

Для отдельной повторной рецензии сохраняйте исходную оценку и выбирайте новые имена:

```powershell
conda run --no-capture-output -n agata-ft python finetuning/report_abc.py compare --ratings evaluation/reports/abc_v1/semantic_ratings_second_review.json --output evaluation/reports/abc_v1/comparison_second_review
```

Перед сравнением проверяются полнота оценок, хеш пакета и неизменность исходных отчётов.
Проверка также отклоняет полный балл при `unsupported_claim=true`, пустые или нестроковые объяснения,
несогласованные response ID и отсутствие ровно одного ответа каждой модели на каждый вопрос.
Скрипт не определяет правильность по ключевым словам и не заменяет содержательную рецензию.
Все 200 ответов четырёх моделей на 42 основных/дополнительных и 8 memorization-вопросов сохраняются;
сравнительный Markdown включает ответы без выборочного отбора удачных случаев.

| `datasets/abc_v1/configs/{A,B,C}.yaml` | Независимые конфигурации с одинаковыми параметрами и отдельными train/validation |

| `outputs/abc_v1/{A,B,C}/trainer_state.json` | Численные training/validation loss на фактических шагах |

| `outputs/abc_v1/{A,B,C}/nvidia_vram.csv` | Выборки драйвера NVIDIA за полный процесс обучения |
| `outputs/abc_v1/{A,B,C}/loss.png`, `vram.png` | Графики, построенные командой `plots` по сохранённым значениям |
| `evaluation/reports/abc_v1/run_manifest.json`, `actions.jsonl` | Frozen manifest с версиями и хешами; журнал последовательных действий |
| `evaluation/reports/abc_v1/{baseline,A,B,C}.json` и `.md` | Общий benchmark, сырые ответы, настройки генерации и признак EOS/лимита |
| `evaluation/reports/abc_v1/{baseline,A,B,C}_memorization.json` и `.md` | Отдельная диагностика точных тренировочных вопросов |
| `evaluation/reports/abc_v1/review_packet.json`, `review_packet_key.json` | Перемешанные ответы для оценки и отдельный ключ раскрытия моделей |

График loss сравнивает ход обучения внутри варианта; численные уровни A/B/C нельзя трактовать как одинаковый
показатель качества, поскольку распределения целевых ответов различаются. Validation loss также относится к
разным наборам. Частота validation зависит от числа эпох; это учитывается при чтении времени работы.

Показания NVIDIA относятся ко всей GPU, включая другие процессы, и опрашиваются примерно раз в секунду,
поэтому могут пропустить короткий пик. В `training_report.json` отдельно сохранены максимумы allocated/reserved
памяти PyTorch. Не следует смешивать эти измерения или считать время на графике VRAM точным профилем вычислений.

Exploratory bootstrap ресемплирует вопросы внутри четырёх доменов. Общие источники и близкие смысловые семьи
могут делать вопросы зависимыми; этот интервал не доказывает независимость наблюдений и не охватывает разброс
между training seed или оценщиками. Для вывода о методе потребуется отдельное подтверждение на новых данных
и повторных запусках. Локальный итоговый отчёт этого пилота находится в `evaluation/reports/abc_v1/`.
