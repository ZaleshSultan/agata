# Книги: локальное извлечение и проверяемые данные

Исходники, извлечённый текст и производные наборы находятся только локально, в игнорируемой Git папке `finetuning/books/`. Скрипты не отправляют книгу во внешние API. Запись производных данных внутри AGATA разрешена только в неотслеживаемые и игнорируемые Git пути; ошибочный публичный путь блокируется до записи. Исходный файл не меняется. PDF требует `pypdf`; TXT, EPUB и DOCX разбираются стандартной библиотекой Python. Зашифрованные PDF и EPUB не обходятся. У сканированного PDF без текстового слоя понадобится отдельное локальное OCR; пустые страницы отмечаются в отчёте.

## Обнаруженный источник

В прежнем эксперименте сохранён `agata_finetune_knowledge_v2/books/6147594.a6.pdf`. По титульным сведениям это Любовь Александровна Поливалина, «Энциклопедия молодой семьи», издательство «Научная книга», 2013. В файле 98 PDF-страниц, и последняя страница явно обозначает конец ознакомительного фрагмента Литрес. Это неполная книга, а не предполагаемое издание 1980–1990-х. Файл ссылается на карточку Литрес с идентификатором 6147594. Доступность ознакомительного фрагмента не даёт права публиковать его текст или производные датасеты.

Выполнено извлечение: `books/polivalina_2013.extracted.json`; проверяемые фрагменты и черновые карточки: `books/processed/polivalina_2013/`. Сведения о главах берутся из PDF-закладок, когда они доступны. Страницы обозначают номера страниц PDF, а не печатные номера книги. Результат извлечения включает контрольную сумму исходника, название, год, издание, главы, разделы и указатели страниц.

Получены 98 фрагментов и 224 автоматические карточки-заготовки. После отдельного чтения страниц и проверки контекста составлено только 10 содержательных карточек: 8 обучающих из главы I и 2 тестовые из полностью исключённого Вступления. Вопросы спрашивают о позиции автора; ответы явно отнесены к источнику 2013 года. Выбраны нейтральные темы уважения, компромиссов, индивидуальности, совместных воспоминаний, самообразования и домашних обязанностей. Обобщения о поле, манипулятивные советы, медицинские и правовые утверждения не включены. Это маленький эксперимент по воспроизведению мнения автора, а не надёжная база семейных рекомендаций.

Проверенные записи сохранены в `books/processed/polivalina_2013/book_knowledge.jsonl`, отдельные вопросы B3/C3/D2/E1 — в `benchmark_book.jsonl`. Остальные автоматические карточки остаются непроверенными. Повторный запуск построения объединённого набора с этими локальными файлами:

```powershell
python finetuning/prepare_dataset.py --book finetuning/books/processed/polivalina_2013/book_knowledge.jsonl --extra-benchmark finetuning/books/processed/polivalina_2013/benchmark_book.jsonl --overwrite
```

`--overwrite` здесь явно заменяет только производные файлы нового Fine-Tuning Lab; старые эксперименты и исходник книги не затрагиваются. Новые перефразировки C не входят в обучение, Вступление целиком оставлено для проверки D. Поскольку выбранные идеи общеизвестны, правильный ответ базовой модели может возникнуть без знакомства с этой книгой; сравнение не доказывает запоминание источника.

## Новый источник

Поместите законно полученный файл в `finetuning/books/`. Выполняйте команды из корня AGATA в отдельном окружении Fine-Tuning. Название, год и издание укажите по титульной странице, а не по имени файла.

```powershell
python finetuning/extract_book.py finetuning/books/my_book.pdf --output finetuning/books/my_book.extracted.json --title "Название по титульной странице" --edition "Издатель и издание" --year 2013
python finetuning/book_pipeline.py prepare finetuning/books/my_book.extracted.json --output-dir finetuning/books/processed/my_book
```

TXT по умолчанию читается как UTF-8; для известного Windows-1251 добавьте `--encoding cp1251`. EPUB обрабатывается в порядке `spine`, DOCX сохраняет указатели абзацев и уровни заголовков. В EPUB/DOCX заголовки второго и следующих уровней считаются подразделами одной главы, а не отдельными группами train/test. Неоднозначные заголовки TXT прописными буквами консервативно остаются в общей главе до явного заголовка «Глава» или «Часть». Скрипт исправляет мягкие переносы и разрывы слов, сохраняет оригинал. Для PDF удаляются только точные повторяющиеся колонтитулы; обнаружение глав без закладок эвристическое и требует проверки. Соседние главы никогда не объединяются в один фрагмент; пересечений между фрагментами не создаётся.

`prepare` создаёт `chunks.jsonl`, `candidates.jsonl`, `rejected.jsonl`, `summary.json`. По умолчанию карточка содержит дословный фрагмент и простой вопрос-заготовку; такой вопрос следует заменить содержательным вопросом перед обучением. Автоматические карточки не выдаются за готовый качественный датасет. Чтобы существующая локальная модель Ollama предложила более естественные вопросы, добавьте `--ollama-model имя_уже_установленной_модели --max-chunks 5`. Модель не скачивается и не заменяется. Перед отправкой текста скрипт проверяет `/api/show`: облачные и удалённые модели, включая локальные псевдонимы, отклоняются; требуются метаданные локальных весов. Прокси и HTTP-переадресация отключены. Не запускайте Ollama одновременно с QLoRA на 6 ГБ VRAM. Ответ и подтверждающий фрагмент обязаны быть полными дословными предложениями из источника, чтобы обрезка не потеряла отрицания и условия; неподтверждённые ответы отбраковываются. Это консервативная текстовая проверка, а не автоматическое доказательство смысла или истинности.

## Редактирование и экспорт карточек

Скопируйте `candidates.jsonl` в отдельный `reviewed.jsonl`. Для каждой пригодной карточки проверьте смысл вопроса, полный контекст источника, отсутствие противоречий и современную применимость. Сам факт наличия текста в книге не доказывает его истинность. Затем заполните:

- `review_status`: `approved` только после проверки, иначе `pending` или `quarantined`;
- `reviewer`: понятное имя проверяющего;
- `review_note`: что именно проверено и какие ограничения остались;
- `partition`: `train`, `validation` или `test`. Все карточки одной `source_id + chapter_id` обязаны иметь одну и ту же часть;
- `training_mode`: `source_attributed`, либо `historical` для спорных или устаревших утверждений.

Рискованные медицинские, юридические и устаревающие технические утверждения по умолчанию не экспортируются. Режим `--allow-historical` допускает только проверенные карточки с годом источника и `training_mode=historical`; ответ обязательно содержит название, дату, атрибуцию и указание, что это историческое утверждение, а не современная рекомендация. Проверка противоречий автоматически ловит разные ответы на одинаковые вопросы, но не заменяет смысловую проверку всей главы.

```powershell
python finetuning/book_pipeline.py export finetuning/books/processed/my_book/reviewed.jsonl --chunks finetuning/books/processed/my_book/chunks.jsonl --output finetuning/books/processed/my_book/book_knowledge.jsonl
python finetuning/prepare_dataset.py --book finetuning/books/processed/my_book/book_knowledge.jsonl
```

Экспорт сверяет provenance с исходным фрагментом и запрещает разделять одну главу между train и test. Непроверенные, противоречивые или неподтверждённые карточки попадают в соседний `book_knowledge.rejected.jsonl`. Файлы не перезаписываются: для следующего запуска выберите новое имя или новую папку. Полностью исключённые главы нужны для категории D; вопросы B/C должны проверять известные обучающие факты и новые перефразировки, а не подмешиваться в обучение. Вывод об усвоении книги требует достаточного числа отдельно проверенных карточек и сравнений до/после. Один воспроизведённый ответ или синтетический факт этого не доказывает.
